## Problem and resulting behavior

Listing tasks currently returns an unbounded array and loads each owner's
username separately. This PR returns a paginated envelope (20 items by default,
at most 100 per page), joins owners with select_related, and adds validated
status, title-search, and ordering parameters. A PK tie-breaker makes ordering
deterministic when timestamps or titles match. List-only filters do not change
detail lookup behavior. A composite index supports owner/status/date queries
with the owner-isolation fix from PR 2 included in this branch.

## Compatibility

Clients must consume `results` instead of the former top-level array.
Nonpositive or malformed page_size follows DRF's default-size fallback;
oversize values are capped. An invalid or out-of-range page returns HTTP 404.
Invalid status/ordering and search over 128 characters return HTTP 400.

## Validation

`python manage.py test`
`python manage.py makemigrations --check --dry-run`

Tests cover pagination boundaries, filters and invalid inputs, deterministic
page boundaries, detail lookup with list parameters, and constant database
query count for 1 versus 20 serialized tasks, descending title ordering, ascending
creation-date ordering, and owner isolation under combined search/status filters.
All 29 branch tests pass. No wall-clock benchmark is claimed.
